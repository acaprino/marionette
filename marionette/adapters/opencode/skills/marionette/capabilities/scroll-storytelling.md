# Scroll Storytelling (scroll-driven pages, heroes and handoff prompts)

Builds websites, landing pages, cinematic heroes and scroll sections organized around **one named scroll moment** (a camera moving through a frame sequence, layers parting from one render, a route drawing itself, a sideways reel, or a looping video hero) on a single `requestAnimationFrame` loop with Lenis, or produces a full-source handoff prompt for another AI builder. `<SS>` below stands for `<package_root>/scripts/scrolltide-ai-studio/plugins/ai-studio/skills/scrolltide-ai-studio`.

## Behavior

`<SS>/SKILL.source.md` and the supporting files it names (`house-style.md`, `patterns/INDEX.md`, `patterns/*.md`, `checks.md`, `handoff.md`) are the full version of this method. Open only the file and section each step needs; where this body differs from an original, the original wins, except for the changes listed under Sources.

0. **Scope by the selected intent.** For `ui.scroll-handoff`, settle the brief (step 1), choose the base (step 2 — connected Scrolltide MCP build or a page built and checked from the patterns first), then follow `<SS>/handoff.md` end to end and skip steps 4–6 except where building from scratch first. Record unused outputs as `not requested: <reason>`.
1. **Settle the brief** (`<SS>/SKILL.source.md`, `## 1. Settle the brief`). State in one line without interrogating the user: who and what, **the scroll moment in one sentence** (propose one if missing), mood in three words, target environment (existing project stack, new Vite + React project, single self-contained `index.html` when no Node/build step is wanted, or a handoff prompt), and scope (full page unless a hero or single section was asked). Consume recorded `offer` and `page_outline` from `visual-direction` when present. Ask only for facts that cannot be invented (real business name); mark missing real-company prices, reviews or customer counts as placeholders.
2. **Choose the starting architecture** (`<SS>/SKILL.source.md`, `## 2. Choose the starting build`, and `<SS>/patterns/INDEX.md`):
   - **If `scrolltide-mcp` is connected**: search with 2–3 words from the brief (`search_library`), pick the single best result and call `get_prompt` on that one item only (daily item limit applies per account; re-opening an item is free). Rebuild it verbatim first (`## 3. Get the base running first`), verify the base once, then rebrand it (`## 4. Make it theirs`). If `search_library` or `get_prompt` reports an item needs Yearly or Lifetime, say so in one line and offer the closest item their plan includes.
   - **Otherwise (default packaged path)**: compose from `<SS>/patterns/INDEX.md` and `<SS>/house-style.md` — **one primary scroll moment** plus quiet support (`reveals.md`, one type move from `type.md`, live readouts when fitting; two heavy stages may share a page only when separated by ordinary sections, never in the same viewport).
3. **Implement the scroll engine and chosen patterns.** Open `<SS>/patterns/engine.md` first, then only the pattern file(s) the brief uses:
   - **Engine (`patterns/engine.md`)**: one `requestAnimationFrame` loop for the whole page; advance Lenis (`lerp: 0.09`, `smoothWheel: true`, `wheelMultiplier: 0.9`; disabled under `prefers-reduced-motion: reduce`), drive pinned `100svh` sticky stages through `pinProgress` and a movement guard (`< 0.00005`), write styles directly (never through React/framework state mid-scroll), declare beats as `[a, b]` progress windows at the top of the file eased with `easeOutCubic` or `smoothstep`, never add CSS transitions to scroll-written properties, and update discrete DOM steps only when the index changes. In an existing project, integrate into its single scroll loop (in Next.js, scroll components are `'use client'`; on Tailwind v3, map `@theme` tokens or scope CSS). Single-file mode loads Lenis from the pinned CDN (`lenis@1.3.11`).
   - **Scroll film (`patterns/film.md`)**: canvas frame sequence (290–480 WebP frames at 24 fps, `d/` 1600w landscape and `m/` 720w portrait, 15–40 KB/frame; never scrub `<video>` via `currentTime`), coarse-to-fine `HTMLImageElement` streaming (stride 32 down to 1, 6 workers; never `ImageBitmap` to avoid mobile OOM), `drawCover` with focal point `(fx, fy)`, and monotone cubic Fritsch–Carlson `createRemap(beats)` speed ramps.
   - **Layered stage (`patterns/layers.md`)**: one wide render cut into aligned transparent WebP layers (`d/` and `m/`), shared `object-position`, `<h1>` placed between mid and near layers, far-to-near exit multipliers, and a solid `.apron` (`110vh`) in the next section's ground colour for a seamless handoff.
   - **Drawn path (`patterns/drawn.md`)**: SVG legs with `pathLength="1"`, dashed ghost underneath, rider positioned via `getPointAtLength`, `tabular-nums` counter (`aria-live="off"`) and step caption (`aria-live="polite"`).
   - **Sideways reel (`patterns/reel.md`)**: pinned horizontal track (~80–90svh per card), focus line (`0.62` vw), distance opacity/scale falloff, inner image drift (`scale(1.15)`), semantic `<ol>`.
   - **Type moves (`patterns/type.md`)**: measured edge-to-edge wordmark (`fitText` via probe size + `ResizeObserver` + `document.fonts.ready`), resolving title (`letter-spacing` + `blur` cleared at 0), live mono HUD readouts (`aria-hidden="true"`), `mix-blend-mode: difference` fixed nav, and one italic serif word per headline.
   - **Reveals (`patterns/reveals.md`)**: progressive-enhancement `.js [data-reveal]` hidden only after script adds `.js` on `<html>`, revealed once by `IntersectionObserver` + `MutationObserver`, always visible without JS or under `prefers-reduced-motion`.
   - **Looping video hero (`patterns/video-hero.md`)**: H.264 MP4 + VP9 WebM + WebP poster (<6 MB), invisible over ground until `canplay` (`readyState >= 3`), staggered CSS `@keyframes rise`, copy placed in a calm frame area (never a flat dark wash over the whole film).
4. **Apply look, media and copy** (`<SS>/house-style.md` and `<SS>/SKILL.source.md`, `## 4. Make it theirs`). Unless a confirmed project `DESIGN.md` overrides them (see Specifics): tinted ink dark ground or warm stone light ground set on `html` and `body` in the first CSS rule; **one accent hue per page** on small working parts (no multi-colour card glows, no purple-to-blue gradient visual, no stacked glassmorphism, no blobs); fluid display clamps, tight display tracking (`-0.02em` to `-0.04em`), `tabular-nums` on dynamic numbers; 999px pill actions, 28px cards, 2–6px technical chips; house timed curves (`cubic-bezier(0.16, 1, 0.3, 1)` entrances, `200ms` hovers, `250–400ms` UI state, `600–800ms` entrances); all copy in one content file (`src/content.ts` in React/Vite builds) with specific numbers and units. Media priority: (1) user's own photos/footage/renders, (2) generated landscape `d/` + portrait `m/` cuts (disclosed if real brand), (3) stand-in assets plainly marked, (4) type-led page — never grey placeholder boxes, never hotlinked external media URLs. Honour `prefers-reduced-motion`, `(hover: none)`, real `<title>`, `alt` text, `aria-hidden` on decorative layers and visible focus.
5. **Check down the whole scroll** (`<SS>/checks.md`). Build cleanly (`npm run build` / `npm run lint` where present), then run `node <SS>/scripts/scrollshot.mjs <target> <shots-dir> --reduced` (use denser `--stops` for long films). Open and inspect every desktop, mobile, first-paint and reduced-motion screenshot plus `report.json`. Fix every blocking issue (errors, broken media, unplayable video, sideways scroll at 390/1440px, missing `<h1>` webfont, first-paint flash, placeholder/old brand copy, foreign hotlinked media), fix every failing scroll checkpoint (stuck pinned stages, framing, readability, holds, apron handoff, reduced motion), and fix the three worst breaks from `house-style.md` (respecting any recorded `DESIGN.md`), then shoot once more. If no browser/Playwright can run, say so plainly and complete the static checks without claiming visual verification.
6. **Handoff prompt (`ui.scroll-handoff`, `<SS>/handoff.md`)**: for a connected Scrolltide MCP build, rewrite in place only title/summary, content file (keeping keys/shapes), palette/fonts (`@theme`/`:root`, `<link>`, stack line in agreement), `index.html`, `Assets` (if user media) and `package.json` name, leaving every other file verbatim; from scratch, build and verify the page first then serialize the finished source in the exact 8-section format (`What this project is`, `How the page works`, `Reproduce this exactly`, `Tech stack`, `Assets`, `Steps to build`, `## File:` blocks with balanced fences, `Design notes`) plus the builder-specific note (Lovable, Bolt, v0, Cursor/Windsurf/Claude Code/Codex, Replit).
7. **Hand over and record** (`<SS>/SKILL.source.md`, `## 6. Hand over`): state where the files are, how to run them, three shots (desktop top, peak scroll moment, mobile) when captured, what was built/changed, and what to replace before shipping (stand-in media, placeholder facts, front-end-only forms). Record `scroll_moment`, `scroll_page` (files written, or `not requested`) and `handoff_prompt` (prompt file/delivery, or `not requested`).

## Specifics

- **Look and motion authority.** A confirmed project `DESIGN.md` (not a starter or reference; minus `unresolved` and `proposed`) wins over `house-style.md` defaults where they differ, and is never rewritten here (`design-file` owns it). A recorded `motion-spec` and `reduced-motion` win for timed transitions (entrances, hovers, UI states); Scrolltide's scroll arithmetic (`patterns/engine.md`, `film.md`, `layers.md`, `svh` stage heights) governs scroll-driven stages and frame scrubbing, which `motion-design` does not cover.
- **One scroll engine.** Never mix Lenis + the single rAF loop with GSAP ScrollTrigger or CSS `animation-timeline` on the same page (`conflicts` with `gsap-scrolltrigger` and `css-scroll`).
- **Runtime dependencies.** Installing `lenis` in a project or `playwright` (`npm i -D playwright && npx playwright install chromium`) for `scrollshot.mjs` follows the runtime-dependency rule: state in one line what is installed, from npm into the project, and verify it answers; a failed Playwright install blocks only screenshot capture, not the page build. `scrolltide-mcp` is optional and remote: never install or require it; when connected, follow the source's rate-limit discipline (one `get_prompt` for the chosen item) and never mention plans unless an item requires Yearly or Lifetime.
- **No promotional credits on pattern builds.** Follow the source's own rule: do not add the "Started from [free build]" credit line when building from `patterns/` alone; only mention Scrolltide MCP once, in one neutral sentence in chat (never in code, comments, files or commits), if the user asks for ready-made builds beyond patterns, and never if they ask not to.

## Checks

- **scroll_moment_named**: the brief names one concrete scroll moment in one sentence, and the built stage (or handoff prompt) centres on it with at most one heavy stage per viewport.
- **single_scroll_loop**: one `requestAnimationFrame` loop (with Lenis when motion is not reduced) drives scroll stages directly via styles without framework state re-renders, CSS transitions on scroll-written properties, or a second scroll library.
- **house_style_or_system_met**: tinted ground on `html`/`body`, one accent hue, fluid display type, clean card/pill shapes, single content file and real/marked copy follow `house-style.md`, or confirmed project `DESIGN.md` values with deviations noted.
- **assets_self_hosted**: every image, frame set, layer and video lives in the project's own `public/` (or documented local paths in a handoff prompt); no hotlinked download URLs and no grey placeholder boxes remain.
- **reduced_motion_and_no_js_hold**: `prefers-reduced-motion: reduce` disables Lenis smoothing and ambient loops while preserving final visible states; `(hover: none)` gates pointer-only effects; reveals stay visible without JavaScript; no sideways scroll occurs.
- **checkpoints_verified**: `scripts/scrollshot.mjs` ran with `--reduced` and desktop/mobile/first-paint shots were inspected with blocking issues fixed and re-shot, or recorded `not-tested` with the reason when no browser/Playwright was available.
- **handoff_prompt_complete**: the full-source prompt contains balanced `## File:` fences, zero leftover brand names, matching font/token declarations across `<link>`, stylesheet and stack, and the target builder's note.
